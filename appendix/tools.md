# 부록 A. 도구별 설치와 설정

확인 기준일: 2026-08-04

이 부록의 내용은 본문보다 빨리 낡는다. 제품의 화면, 메뉴 이름, 설치 명령, 권한 설정은 몇 달 단위로 바뀐다. 기준일이 오래되었다면 아래 내용은 무엇을 확인해야 하는지의 목록으로만 쓰고, 실제 절차는 각 도구의 현재 문서에서 확인한다.

## 도구를 세 범주로 이해하기

제품 이름을 외우는 것보다 범주를 구분하는 편이 오래간다.

웹 대화 환경은 브라우저나 앱에서 질문하고 파일을 첨부하는 방식이다. 시작이 빠르고 준비가 필요 없다. 결과는 대화 기록에 남고, 사용자의 파일 시스템에는 아무것도 남지 않는다.

폴더 기반 에이전트 환경은 로컬 작업 폴더를 지정하고 그 안의 파일을 직접 읽고 고치는 방식이다. 시작하려면 폴더와 지침 파일이 필요하고, 대신 결과가 파일로 남는다. 이 책이 다루는 작업 대부분이 여기에 속한다.

혼합 환경은 대화 인터페이스를 유지하면서 연결된 폴더, 도구, 외부 서비스를 함께 쓰는 방식이다. 편의성과 파일 소유가 섞여 있으므로, 무엇이 사용자의 파일에 남고 무엇이 서비스 안에만 있는지를 매번 확인해야 한다.

## 설치할 때 확인할 것

어떤 도구를 쓰든 다음 여섯 가지는 확인한다. 이 목록은 제품이 바뀌어도 유지된다.

첫째, 그 도구가 실제로 읽는 지침 파일의 이름이다. 도구마다 다르고, 같은 도구도 버전에 따라 다르다. 이름을 확인하지 않고 지침을 쓰면 규칙이 적용되지 않은 채로 작업이 진행된다.

둘째, 작업 폴더를 지정하는 방법과 그 범위다. 지정한 폴더의 상위나 하위까지 접근하는지, 심볼릭 링크를 따라가는지 확인한다.

셋째, 파일 수정 권한의 범위다. 읽기만 하는지, 쓰기까지 하는지, 삭제도 하는지, 그리고 각 동작에 사용자 승인이 필요한지 확인한다.

넷째, 외부 서비스 접근 권한이다. 웹 검색, 메일, 일정 같은 외부 연결이 기본으로 켜져 있는지 확인한다. 이 책이 다루는 방식에서는 웹 검색이 기본으로 꺼져 있어야 근거의 추적 가능성이 유지된다.

다섯째, 세션이 끝난 뒤 무엇이 남는지다. 대화 기록이 어디에 저장되는지, 파일 변경이 즉시 반영되는지 확인한다.

여섯째, 실행 환경과 색인 파일을 둘 위치다. 동기화 폴더 안에 실행 환경이나 색인을 두면 두 기기에서 동시에 쓸 때 충돌이 생긴다. 본문 4장에서 다룬 사고가 이 범주의 문제였다.

## 설치 확인 절차

도구를 설치한 뒤 다음을 순서대로 확인한다.

1. 빈 폴더를 만들고 그 폴더에서 세션을 시작한다.
2. 지침 파일에 눈에 띄는 규칙을 하나 적는다. 예를 들어 "모든 답변의 첫 줄에 현재 작업 폴더 이름을 적는다"처럼 지켰는지 바로 보이는 규칙이 좋다.
3. 새 세션을 열고 아무 질문이나 던져 그 규칙이 지켜지는지 본다. 지켜지지 않으면 그 도구는 그 파일을 읽지 않는 것이다.
4. 파일을 하나 만들게 하고 실제로 디스크에 생겼는지 확인한다.
5. 세션을 닫고 새로 열어, 이전 세션의 내용을 자동으로 기억하지 않는다는 것을 확인한다.

5번이 중요하다. 같은 폴더에서 새 세션을 열어도 이전 대화가 이어진다고 가정하면 안 된다. 필요한 상태는 파일에 남겨야 한다.

## 공유 채널의 구독과 조직 간 연결

확인 기준일: 2026-08-05

25장이 다루는 채널 배치는 개인 workspace 하나와 연구실 workspace를 잇는 구성이다. 구독은 연 단위로 하고, 교육 기관 할인을 적용하면 연간 요금이 3달러 수준이다. 요금제의 구성과 할인 자격 조건은 이 부록의 다른 항목보다도 자주 바뀌므로, 실제로 신청하기 전에 공급자의 현재 안내를 확인한다. 특히 교육 기관 할인은 소속 증빙과 심사를 요구하는 경우가 있고 적용되는 요금제가 한정될 수 있다.

조직 간 연결 기능은 한쪽에서 신청하는 것으로 열리지 않는다. 양쪽 workspace의 관리자가 각각 승인해야 채널이 이어지므로, 연구실 workspace의 관리자에게 어느 채널을 왜 잇는지 미리 설명해야 한다. 승인이 두 번 필요하다는 사실 때문에 연결은 즉시 열리지 않고, 채널 하나를 잇는 데 며칠이 걸릴 수 있다. 연결을 끊는 일도 같은 방식으로 양쪽에서 이루어진다.
