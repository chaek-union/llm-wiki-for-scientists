# 부록 C. 용어 사전

본문에서 처음 나올 때 설명한 용어를 모았다. 괄호 안의 숫자는 그 용어를 소유한 장이다.

## 기본 개념

지속적인 작업 기억 (1장)
세션이 끝나도 남아서 다음 작업의 출발점이 되는 기록. 이 책이 LLM-Wiki를 처음 설명할 때 쓰는 말이다.

LLM-Wiki (1장)
폴더 안의 Markdown 문서를 사람이 소유하고 AI 에이전트가 함께 읽고 고치는 지식 작업 환경.

위키 (1장)
문서 사이의 연결과 지속적인 개정이 중심인 문서 체계.

에이전트 (2장)
목표를 해석하고 폴더를 탐색하며 파일을 읽고 고치는 등 여러 작업 단계를 이어서 수행하는 AI. 현재 대화 안에서만 반응하는 챗봇과 구분한다.

세션 (2장)
한 번의 작업 흐름. 폴더는 여러 세션에 걸쳐 유지되는 맥락이고, 세션은 그 위에서 일어나는 일회성 작업 시간이다.

작업 폴더 (2장)
에이전트에게 지정하는 폴더. 보이는 자료, 작업 범위, 적용 규칙, 지속 기억의 네 가지가 함께 정해진다.

지침 파일 (2장)
에이전트가 이 폴더에서 어떻게 일해야 하는지를 적은 문서. 도구마다 읽는 파일 이름이 다르다.

## 구조

원자료 (1장, 3장)
논문, 회의록, 데이터, 링크, 이미지처럼 다시 확인할 수 있는 근거. 고치지 않는 층이다.

Source note (4장)
원문 전체를 읽고 고정된 항목에 맞춰 압축한 독서 기록. 수치나 조건이 판단을 좌우하는 대목에서는 여기서 원문으로 내려간다.

Paper wiki page (4장)
논문을 검색하고 연결할 수 있는 지식 그래프의 한 노드로 만든 페이지. 다른 논문과 종합 문서로 가는 링크를 담는다.

Category (3장, 4장)
논문을 나중에 어떤 질문으로 다시 찾을지에 대한 결정. 같은 논문도 위키의 목적에 따라 다른 범주에 놓인다.

Synthesis layer (4장, 5장)
여러 논문이 만나 주장이 강화되거나 좁혀지거나 반박되거나 대체되는 층. overview, concept, question 문서로 이루어진다.

Overview (5장)
분야의 현재 지식을 종합한 문서.

Concept (5장)
안정된 개념, 방법, 기전을 다루는 문서.

Question (5장)
근거가 아직 얇은 열린 질문을 다루는 문서.

Schema (3장)
구조, 명명법, 작업 규칙을 정한 운영 계약. Karpathy 원형의 세 번째 층이다.

Wikilink (4장)
문서 사이를 잇는 링크. 파일을 여러 곳에 복제하는 대신 하나의 정본 위치와 여러 링크를 쓴다.

## 동작

Ingest (3장, 4장)
새 자료를 읽고 위키와 색인, 로그를 갱신하는 일. 파일을 폴더에 복사하는 것으로 끝나지 않는다.

Query (3장, 5장)
관련 페이지를 찾아 근거 있는 답을 만들고, 재사용할 가치가 있는 답을 다시 위키에 저장하는 일.

Lint (3장)
모순, 오래된 주장, 고립된 페이지, 빠진 연결과 지식 공백을 찾는 일.

BM25 (5장)
질문의 단어가 각 문서에서 얼마나 구별력 있게 나타나는지로 문서를 순위화하는 검색 방식. 답을 만들지 않고 읽을 후보를 좁힌다.

Deep Synthesis (5장)
여러 논문의 설계, 결과, 경계와 서로의 관계를 비교해 하나의 판단을 만드는 일.

Deep Structure Analysis (6장)
한 논문의 모든 인용을 등장 절과 기능에 따라 지도화하고, 중요한 인용의 원문까지 읽어 그 논문의 지적 계보와 신뢰 전략, 데이터 출처 구조를 드러내는 분석법.

## 운영

SSOT (12장)
Single source of truth. 어떤 정보의 최신 상태를 소유하는 단 하나의 위치. 복사본을 만들면 어느 것이 최신인지 알 수 없게 된다.

Owner (12장)
특정 정보나 규칙을 소유하는 문서 또는 작업 공간.

Handoff (15장)
한 에이전트가 만든 결과를 다음 단계가 쓸 수 있도록 정리한 인계 문서. 언제 만들어졌는지가 반드시 들어간다.

Claim–evidence 지도 (11장)
각 주장에 대해 그것을 지지하는 근거, 근거의 강도, 그리고 그 주장이 무너지는 조건을 함께 적은 표.
